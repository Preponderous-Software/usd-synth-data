# World examples

Each example turns a world from outside this package into a labelled dataset with the stock
usd-synth-data Blender worker, pass reader and COCO writer. The examples share
[`common/worldviews.py`](common/worldviews.py): the per-view layer (camera, sun, sky), rendering
a run, reading labels from the Object Index pass, and writing `annotations.json` and the
`render` and `throughput` parts of `meta.json`. Each example only builds its scene and samples
its cameras. [`common/contact_sheet.py`](common/contact_sheet.py) draws the contact sheets for
Roam and Barony.

| Domain | Example | World comes from | Labelled classes | Instance = |
|---|---|---|---|---|
| Minecraft | [`minecraft/`](minecraft/) | a [Minecraft-USD-Exporter](https://github.com/Dans-Plugins/Minecraft-USD-Exporter) terrain export | tree, water, ore, sand, stone | a connected group of blocks |
| Roam | [`roam/`](roam/) | a [roam-usd](https://github.com/Preponderous-Software/roam-usd) stage (from a save, or generated by Roam's own generator) | tree, stone, ore, creature, structure, food | a tree, outcrop, vein, home or single creature / item |
| Barony | [`barony/`](barony/) | game-state JSON from a running [Barony](https://github.com/Preponderous-Software/barony) backend | castle, village, army | one castle, village or army |
| Beyond Nations | not yet | — | — | see below |

## Beyond Nations: not added yet

[Beyond Nations](https://github.com/Preponderous-Software/beyond-nations) (C#, .NET 8) was
checked on its `develop` branch (commit `4cc43dd`, 2026-10-18). Its world cannot be exported
without writing an exporter first:

- **No saves.** Nothing in `BeyondNations.Core` or `BeyondNations.Desktop` writes the world
  to disk.
- **The headless path has no labels.** `BeyondNations.Desktop` takes `--seed`,
  `--exit-after-frames` and `--screenshot-after-frames`. Those give a reproducible RGB
  screenshot, but nothing says which pixels belong to which entity, and it needs an OpenGL 3.3
  window.
- **The state is easy to read once code can run.** `BeyondNations.Core` has no engine
  dependency. `new Simulation(gameConfig)` with a world seed builds the world, and
  `fixedUpdate` advances it with no window. Each entity (`AppleTree`, `Sapling`, `Rock`,
  `Pawn`, `Chicken`, `Settlement`, `ItemDrop`) has a position and an `Appearance`: a list of
  primitives (cube, capsule, cylinder or sphere, each with an offset, scale and colour). Ground
  tiles are `Location`s with a position, scale and colour. `WorldSnapshot.capture` flattens
  all of this into one primitive list per frame. It drops which entity each primitive belongs
  to, so an exporter has to walk `EntityRepository` itself rather than use the snapshot.

What is needed:

1. **An exporter**: a small .NET console program that references `BeyondNations.Core`. It
   builds a `Simulation` from a seed, runs N fixed updates, and writes every entity (id, type,
   position, appearance primitives) and every ground location as JSON or as a USD stage. It
   could be a flag on the game, or its own repository like roam-usd. Building it means
   changing Beyond Nations or creating a new project, which this repository does not do.
2. **A .NET 8 SDK** wherever the exporter runs (none is installed on the machine these
   examples were made on).
3. **An example here**, built like `barony/`: read the export, mesh each entity's primitives
   (one instance per entity; classes such as tree, rock, pawn, chicken, settlement, item), and
   aim views as the other examples do.
4. **License care.** Beyond Nations is under the Preponderous Non-Commercial License. An
   example here may read an export, but no Beyond Nations code, assets or saves may be
   committed to this MIT repository.
